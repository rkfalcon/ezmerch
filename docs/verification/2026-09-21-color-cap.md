# 25-color template cap and live upload timing

## Enforcement

- Admin template cards display enabled/catalog counts (including catalog colors that do not yet have generated mockups).
- Global color picker stops selecting at 25, allows deselection at the limit, explains the cap, and replaces Enable all with Enable up to 25 for larger catalogs.
- API validates the unique selection and rejects a 26th color. Database constraint prevents unlimited resolved templates and selections above 25, including service-role writes.
- Existing saved staple-shirt 25-color selection preserved. Unlimited templates converted to explicit selections; oversized catalogs use common Black/White/Navy defaults followed by catalog order. Catalogs below 25 retain all colors.
- New template creation, editing and preset activation persist explicit capped colors.
- Generation now filters to selected colors before printfile planning. Previously enabled colors only affected ordering, so disabled colors still consumed work. Sizes remain unrestricted within selected colors. Existing saved batches are not regrouped.
- Existing storefront products inherit global selections through the existing availability trigger; historical orders/variant records remain intact.

## Additional throttle finding

During the run, mockup creation returned HTTP 429 despite 32-second reservation spacing. Representative observed sequence: success with remaining=0/reset=28 at 18:18:12 UTC, then 429/retry-after=27 at 18:18:45 UTC. Polling independently reported limit=120; creation reported limit=2. No concurrent EZMerch manual mockup-route requests appeared in the inspected logs. The provider-side reason for the reset discrepancy is not established.

Added exhausted-quota feedback: once a successful creation reports remaining=0, extend the shared next-creation reservation to at least 65 seconds after that response (respect longer resets, bounded to five minutes). Downloads, polling and publication continue during that interval. Database function can only extend, not shorten, a reservation. Migration 20260921182633 applied; production service-role RPC verified. Existing 429 recovery remains. This was deployed during the test; the run is not a clean isolated benchmark of this final adjustment. Old deployment queue consumers can finish their existing chains using the original code, while sharing the same DB reservation.

Full suite after this change: 137 passed; TypeScript and scoped ESLint pass.
